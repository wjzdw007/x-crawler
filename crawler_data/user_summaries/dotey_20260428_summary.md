**新工具/技术**（如有）
- Warp（终端客户端，已开源，AGPL）：把 AI 能力嵌入终端，支持 Claude Code、Codex、Gemini CLI 等，并接入多款开源模型（Kimi、MiniMax、Qwen），社区贡献流程以“AI 优先”为核心。  
- OpenAI on AWS（GPT‑5.5、Codex、Managed Agents 上云 Bedrock，限量预览）：企业可在熟悉的 AWS 环境里直接用 OpenAI 模型与托管智能体，简化合规与账单整合。  
- Open Claude Design（开源模仿工程）：产出以 React 组件为主、界面与交互较完善的设计模板，开源版目前产出更偏 HTML 雏形但可学习借鉴。  
- Learn Harness Engineering（开源课程）：教如何为 AI 编程助手搭建“工作台”，包含指令、状态、验证、范围、会话等可复用模板和实战项目。  
- Ghostty（终端模拟器）迁移决策：作者因 GitHub 稳定性与可用性问题把项目迁出，提示开源托管风险与备份重要性。

**核心观点/方法论**（如有）
- 上下文窗口有硬限制：再强的模型也受上下文长度约束，上下文“塞满”会降低效果，带来 token 焦虑与设计权衡的重要性。  
- 从 ChatBot 到 Agent 的范式转变：现代会话系统是有工具与运行环境的 Agent，建议让模型自行做验证与迭代，提升产出可靠性。  
- “人管方向，AI 干活”的协作模式：Warp 提倡让 AI 负责执行（写代码、跑测试），人负责决策与方向，把社区贡献流程结构化为 AI 驱动的生产力路径。  
- 世界模型分层与领域法则（来自 88 页综述）：能力分 L1（短步预测）、L2（多步且遵守领域规则）、L3（自我诊断与实验设计），不同领域（物理、数字、社会、科学）对“合法状态转移”约束差异大。  
- 符号化 vs 隐式表示的权衡：历史上可编辑的符号规则更利于可解释与可修改的世界模型，而当前神经网络把规则埋在权重中，L3 场景下这成为障碍。  
- 对“六个月内无人工”类论断持谨慎：对复杂项目的实践表明短期完全替代不现实，更多是流程与工具改造而非瞬间失业。

**实践经验/案例**（如有）
- Opus vs Sonnet 写作体验：对格式固定、要求不高的文档两者差别小；对高质量写作（高要求）Opus 表现更好。  
- GPT‑5.5 后的工具组合：作者更多用 Codex + ChatGPT，写作能力与绘图能力提升且目前感觉“没有 token 焦虑”。  
- 用 Agent 做自我验证：在生成提示词或产物时，让 ChatGPT 自行验证并据此迭代，再人工验收，通常结果更稳更好。  
- 开源项目对比（Claude Design vs 开源复刻）：Claude 原产出为完善的 React 组件与流畅交互，开源复刻已相当不错但交互与完善度仍有差距，适合学习借鉴。  
- 企业上云与工具链整合案例：OpenAI 把 Codex 与 Managed Agents 上 Bedrock 后，企业能在 AWS 里直接整合模型、合规与计费，降低迁移成本并把 Codex 用途扩展到文档、分析等非编码场景。
