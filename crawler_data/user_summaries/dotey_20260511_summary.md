**新工具/技术**
- Agent Pets（基于 MCP 的“像素宠物”）：通过 MCP 与 Agent 连接，提供情绪化的本地静态反馈界面（仅视觉/情绪价值）。  
- MCP（Message/Module Connector/Protocol）：统一工具接入规范，让 Agent 能调用外部工具和资源。  
- Agent Skills：把领域知识和最佳实践封装成可复用能力，扩展 Agent 执行“怎么做”的能力。  
- Codex App（含原始插件市场）：桌面/多栏 Agent 平台，侧重把 Agent 做成“几乎能做任何事”的入口并尝试插件化。  
- Claude Code 的 agent view：会话总览界面，可在列表中直接偷看/回复会话，并支持 /bg 或 claude --bg 背景任务指令。  
- Cursor（模型中立）：优势是可接入任何顶尖模型，劣势是没有自研顶尖模型作为护城河。  
- baoyu-skills / Confirmo（实践工具与原则）：开源 Skill 热度高但难变现；Confirmo 强调不干扰用户 Agent 执行、以监听为主的设计原则。

**核心观点/方法论**
- 三栏界面是 Agent 交互的当前最优解：左会话、中对话、右工作区让 Agent 输出与人工复核/编辑闭环化，适配代码和多文件工作流。  
- 插件化是实现“Agent for everything”的关键：平台只做调度，把文件编辑、垂直能力交给插件生态来扩展和商业化。  
- MCP + Skills 只解决“连接”和“能力复用”的一半问题：缺的是“二次编辑/最后一公里”体验与统一编辑插件。  
- 不要让情绪类 Pets 干扰核心任务：依赖 MCP 的 Pets 会给模型增加额外心智负担，可能降低任务效率。  
- 平台经济与商业化路径：Skill 易被复制、难变现，插件/应用商店模型能提供付费和版权保护，从而激励开发者持续投入。

**实践经验/案例**
- Codex 的右侧工作区在 4 月更新中幅度最大，用户期待在 Agent 内直接完成二次编辑（代码/Markdown/PPTX 等）。  
- Claude Code 的 agent view 已做成研究预览，能显著减少在多会话间切换的成本，提升并行会话管理效率。  
- baoyu-skills 虽然接近 2 万 Star，但收入为 0，说明 Skill 层面缺乏变现机制。  
- 对中小团队的机会窗口：若 Codex/Cursor 等平台跑通插件生态，做插件比独立做 Agent 更快拿到用户与分发入口，先入者有明显冷启动红利。
