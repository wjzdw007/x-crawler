**新工具/技术**
- baoyu-skills（微信群聊总结 Skill）：基于 wx-cli 读取微信群数据，自动生成群聊总结；作者说明不提供 wx-cli 配置帮助，需看项目文档。
- wx-cli：用于从本地微信导出/读取群聊数据，是 baoyu-skills 的依赖工具；使用时需注意权限与隐私管理。
- Claude for Small Business（Anthropic）：把 Claude 嵌入 QuickBooks、PayPal、HubSpot、Canva、DocuSign 等 SaaS，提供 15 个预设小企业技能（工资、催款、合同等）；收费随 Claude 订阅与所用 SaaS 计费。
- Claude Code + Claude Opus 4.6：作者提到在某些任务上效果最佳，提示在选择模型栈时可优先考虑该组合。
- Codex 集成到 ChatGPT 手机 App：手机端作为远程监控/批准界面，实际执行仍在开发机器上，使用 secure relay 保持会话与安全；首发支持 macOS，Windows 很快跟进。
- Cursor 的 "Plan New Idea"：设计模式被认可但存在多语言不一致问题（中文提示生成英文文档），需要改进语言继承逻辑。

**核心观点/方法论**
- 上下文（Context）与上下文窗口（Context Window）不同：前者是 Agent 实际拥有的信息集合，后者是模型一次能处理的 token 容器；区分有助于架构设计与调优。
- Context Engineering 是关键能力：在有限窗口内选择/压缩最有价值的信息（摘要、选择性检索、清理中间结果）直接决定 Agent 效能与成本。
- 产品化需兼顾安全和可接受性：Anthropic 的做法（人为启动审批、默认不用于训练企业数据）说明商业落地要处理权限与隐私顾虑才能获得采纳。
- 细节 UX 决定采纳率：语言一致性、远程可视化审批等体验细节会显著影响用户是否愿意长期使用和付费。

**实践经验/案例**
- baoyu-skills 实操教训：依赖第三方 CLI 时要清晰声明支持边界和隐私风险，减少用户因为安装/权限问题产生的支持负担。
- Cursor 案例：多语言输出不一致是典型的产品痛点，直接修法是让生成文档继承提示词语言或在模板里显式指定语言参数。
- Anthropic 小企业落地策略：通过深度集成常用 SaaS + 本地化培训（线下半日、线上课程）快速推动采纳，但也会侵蚀传统 SaaS 的入口价值。
- Mole Mac（Mole 桌面端）经验：社区驱动、高质量 issue/PR 和用心的视觉设计可以在短期内放大影响力并提高付费转化。
- Codex 手机端场景验证：非常适合远程监督、审查 diff 与批准长期任务，但受限于平台支持与安全策略，短期内无法完全替代开发端的工作流。
