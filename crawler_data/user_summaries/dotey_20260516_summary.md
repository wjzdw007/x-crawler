**新工具/技术**（如有）
- Sublime：回归轻量编辑器，内存约300MB，适合主要做语法高亮和文件编辑，节约资源。
- Zed：现代轻量代码编辑器，内存占用小，支持登录 OpenAI 与 GitHub 并共用 Token，便于 AI 集成与工作流统一。
- Codex（侧聊特性）：引入 /side side-chat，用于在主线程外进行非侵入性问答与轻量探索，系统提示限制修改性操作并只允许非破坏性检查。
- Claude Code Desktop：桌面代码/协作工具，存在 Plan mode 状态记忆、sidebar 分组和右侧 Panel 布局等 UX 问题，提示需要产品改进以提升开发者体验。

**核心观点/方法论**（如有）
- 长任务要拆成小阶段并为每阶段设计明确的验证方法（单元/集成/端到端测试等），验证是防止跑偏的核心。
- AI 最适合“可验证的翻译/迁移”类长期任务（例如大规模代码从一种语言迁移到另一种），因自动化测试能保证连续运行的安全性与正确性。
- Agent 产品要把 Model 与 Harness 明确分工：Harness 负责落地、反馈回路与用户连接，衡量 Agent 是否有用需靠产品化指标与用户信号。

**实践经验/案例**（如有）
- 编辑器选择应以工作模式为准：当不常手写代码时，Sublime 或 Zed 等轻量工具足够且更省内存。
- Zed 能共用 OpenAI/GitHub Token，降低配置摩擦，适合频繁调用模型的个人或团队工作流。
- DeepSeek 招 Agent Harness PM 的职位说明是一个参考模板：强调产品路线、与研究员深度协作、指标化验证、Prompt/Context/Harness 实践与社区运营能力。
- 在实际 AI 编程中，作者建议每步产出都能被人工 review，避免一次性让 AI 连续长时间跑大量产出导致难以复核。
- Codex 用量周期性重置提醒要合理安排配额；对 Claude Code Desktop 的吐槽也反映出工具 UX 直接影响开发效率。
- 总结：今日主线是“向轻量化工具倾斜 + 强调验证与 Harness 工程”，关注点为资源效率、可验证性和产品化落地能力。
