**新工具/技术**（如有）
- kimi-code（TS 版）：原 kimi-cli 从 Python 完全重构为 TypeScript，目标是更现代的 CLI/交互与可维护性。
- pi-tui：用于构建终端 UI 的 TypeScript 库，适合交互式 CLI/Agent 控制台。
- Claude Code（参考灵感）：被提到为启发某些功能实现的来源。

**核心观点/方法论**（如有）
- 不建议单独去做通用 Agent Harness：模型公司在模型能力和升级节奏上占优势，单打独斗容易被模型更新抹平差异。
- 基于成熟 Agent Harness 去做方案更有价值：聚焦行业方案、工作流与体验层能形成长期护城河。
- MCP 与 Skills 的定位：MCP 解决连接/接口，Skills 解决领域知识，但二者只是底座，仍需上层的行业化工作流与数据。
- Agent 作为未来操作系统的观点：少数公司提供模型和 Harness，其他团队应在其上构建垂直应用与体验。

**实践经验/案例**（如有）
- kimi-cli -> kimi-code 重构启示：选对语言/工具栈（TS+pi-tui）能加速交互迭代并利于生态集成。
- 垂直化可落地方向：为传统工作流重新设计 AI-native Agent 流程；在人机闭环处重构 UI/UX。
- 数据与共建是关键：高质量的垂直领域数据整理和与模型/平台的共建，能形成实质性竞争力。
- 产品化建议：把精力放在可组合的 Skills、行业规则、审计与安全等上，而不是重复造底层模型或通用 Harness。
- 团队分工启示：平台方维护模型与 Harness，行业团队专注流程、体验和数据，能更快交付实际价值。
- 风险与对策：上层方案需对模型能力演进保持弹性，设计可插拔、易演进的架构以降低维护成本。
- 简短结论：与其竞争做通用底座，不如在成熟底座上深耕垂直领域、体验和数据，产出更难被替代的价值。
