**核心观点/方法论**（如有）
- Agent 应用 ≠ 传统 App+AI：区别在“执行主体”——传统是人操作、AI 辅助；Agent 应用是人下指令、Agent 代为操作并完成任务，代表自动化边界的提升。  
  为什么重要：这决定了产品设计、授权/安全边界和用户体验（从“交互”转为“指挥”）。  
- “Markdown 当源代码”有条件成立，但存在三大问题：确定性差（同一 Markdown 在不同模型/Agent/操作下结果差异大）、很难清晰描述 UI/交互、以及安全风险（提示词注入类似早期代码+数据混淆导致的提权漏洞）。  
  为什么重要：若把生成式系统当做开发主流程，上述问题会直接影响可复现性、可售性和安全性。  
- 安全类比（提示词注入 ↔ 可执行数据分离）：需要把“提示/数据”与“执行能力”做更严格的边界和防护设计。  
  为什么重要：避免模型被恶意指令利用，防止执行层级的越权。

**实践经验/案例**（如有）
- Hermes Agent + baoyu-infographic：直接产出高质量信息图，说明 Agent 垂直 skill 在生产资产方面效率高、可用于快速原型或内容创作。  
- Agent 在办公自动化场景（以 Codex 为例）：可以全程操作 PPT/PPTX，完成“替人操作”的需求，是真正把工作流程自动化的示例。  
- Markdown → 代码/产品 的实践陷阱：在实际交付中，经常遇到输出不一致与 UI 可用性不足，强调需要更严格的规范、可测试的工具链和人机混合验证流程。  
- Stack Overflow 变现案例：社区提问量下降但营收翻倍——靠内部知识库与数据授权给 AI 公司变现，显示内容平台在 AI 时代可通过企业产品与数据授权实现商业化，但数据“矿”有老化风险。  
- 华为 Tau scaling / LogicFolding（转发分析）：短期能通过 2D→3D 堆叠、逻辑折叠获得时钟频率与能效红利（如 PPT 上的时钟/能耗改进），但代价是散热、设计复杂度与制造成本上升，且边际收益递减；对可复制性与长期可持续性持谨慎态度。
