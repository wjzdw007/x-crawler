**新工具/技术**（如有）
- Codex Handoff：跨设备任务迁移功能，能把正在进行的聊天/代码任务连同本地 Git 状态迁到远程主机继续运行，再拉回本地接着做。  
- Cowart（插件）：基于 Codex 的无限画布工具插件，尝试更直觉、留痕的图片标注与交互式编辑流程。

**核心观点/方法论**（如有）
- 错误处理顺序：先恢复生产 → 再找根因 → 最后采取防范措施；保证可用性优先，便于后续追查。重要因为线上事故成本高，恢复速度决定影响面。  
- 不要盲目把所有措施塞进 AGENTS.md：只有当根因是“AI缺乏项目特定知识/约定”时才写入，过多规则会降低规则质量和模型响应精度。  
- 让 Agent 产出更贴需求：先做需求分析与系统设计（用 plan 模式），拆分可验证的里程碑，形成明确的上下文和验收标准。  
- 降低上线不稳定性的工程做法：细粒度提交便于 Code Review，人仍需对业务边界把关；结合自动化单元/集成/端到端测试与 CI。  
- 线上修复现实路径：AI 应该做定位与生成修复建议，人来复核并通过 CI/CD 自动化发布；全自动闭环当前不成熟。  
- 日志与可复现环境是自动化修复前提：结构化日志（请求ID、用户ID、关键参数）和与生产接近的测试环境，能让 Agent 有意义地还原现场。

**实践经验/案例**（如有）
- Codex Handoff 的使用前提：在 Settings > Connections > SSH 配置远程主机，远端也装 Codex 并允许连接，双方用同一 ChatGPT 账号。  
- Git 状态完整迁移：未提交的改动、当前分支会随任务一起迁移；若本地打开的是子目录，远端需保存相同子目录路径且能访问同一远程仓库（私有仓库需 SSH key/认证）。  
- AGENTS.md 应用场景：把团队特有的命名、目录或隐含 API 约定写进去是合理的；但对可用测试、架构或流程层面的问题应通过测试或流程改进解决。  
- 实操建议：让 Agent 先出 plan 并提问以达成共识；把测试与部署流程自动化（CI/CD、feature flags、灰度发布），并保留人作为最终审查者。
