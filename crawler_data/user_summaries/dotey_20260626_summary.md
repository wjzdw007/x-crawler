**新工具/技术**  
- Codex 趋向于 Agent OS：从单一办公自动化演进为能调度/管理多 agent 的平台，成为跨部门工作流的“操作系统”。  
- GPT-5.6 系列（Sol / Terra / Luna）：三档产品定位分别为旗舰、日常与经济，带来不同性能/价格权衡。  
- Sol 的 ultra/max 模式：max 用于更深推理，ultra 通过并行子 agent 处理复杂任务，等同模型内建的多 agent 协同。  
- Sol 的安全流水线：内置实时分类器、复审大模型和大规模自动化红队（约70万 A100 等效 GPU 小时）训练是重要防护手段。  
- PPT Master / 新的 PPT skill：能导出可编辑 PPTX、生成 AI 配图，并在 Agent 内置浏览器中进行标注和编辑，提升产出可用性。  
- Cerebras 加速版本：7 月可能上线，号称推理速度可达每秒 ~750 token，面向高吞吐场景。

**核心观点/方法论**  
- Agent OS 的时代：平台级 agent 管理比单个 agent 办公插件更具长期价值，因为它承载组织级协调与权限。为什么重要：降低重复开发、统一安全与数据治理。  
- 模型内多 agent（Sol Ultra）趋势：如果模型能自拆任务并并行求解，开发者对外部编排的需求会显著下降，产品迭代路径会被重塑。  
- 分级开放与合规优先：OpenAI 对 GPT-5.6 限量开放体现出能力释放必须与政策/安全考量并行，短期会产生“可得性不均”。  
- 成本-性能权衡落地：Terra 提供接近上一代性能但成本大幅下降的选项，对大规模推理极具吸引力；Luna 则适合极低成本、高吞吐。

**实践经验/案例**  
- PPT 工具实践：dotey 自测的新 skill 强调“可编辑输出 + AI 配图 + 浏览器内标注”，对需要快速交付高质量演示的人很实用。  
- 团队选型建议：对大规模推理或批量任务优先评估 Terra 的性价比，短期能显著降本。  
- 架构影响：若 Sol Ultra 稳定，优先考虑让模型承担复杂任务拆分与汇总，减少工程上对 agent 编排层的投入。  
- 安全/红队实践：借鉴 OpenAI 的大规模自动化红队与实时复审思路，团队应把“模型自检 + 人/模型复核”纳入上线流程。
