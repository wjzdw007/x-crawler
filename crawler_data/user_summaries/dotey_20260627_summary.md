- Anthropic 的 Mythos 5 部分解禁：准许约100家美国政府机构和关键基础设施单位使用，Fable 5 面向普通用户仍下线（表明分级发布机制）。
- Codex / Claude Code 的上下文压缩与 Prompt Caching：降低长会话成本，配套功能有 fork（从某对话位置分支）和 /btw 或 /side（在会话内做“旁路”提问）。

**核心观点/方法论**（如有）
- 前沿模型的“可用性＝风险管理结果”：政府和企业会基于双用风险做逐客户/逐场景的准入，这将使发布前审查常态化（对部署策略影响大）。
- 投资方利益可能反向影响产品可用性：大股东/云厂商在安全发现时会推动紧急下线或整改，企业需把治理/合规纳入产品决策。
- 会话设计应以“上下文纯度”与可控成本为原则：用上下文压缩 + fork + /btw 等机制，把长期会话变成可维护、低成本的工作流。
- 基础设施为先：长期稳定的迭代依赖扎实的基建和工程文化（“老登”风格），短期概念化落地容易但风险更高。

**实践经验/案例**（如有）
- 开源渲染思路实用：先把内容抽成 JSON spec，再用本地渲染同时输出可编辑格式，方便生成动图/图片和后续编辑，适合文档→视觉化流水线。
- Anthropic 案例教训：在面向敏感场景（网络安全/生物）部署模型前，要主动与监管沟通并准备分级访问与审计策略，预案包括回退、白名单和本地化控制。
- 模型迁移与升级：当平台下线（如 GPT-4.5 在 ChatGPT 的退场），需通知用户、迁移自定义 GPTs 并验证 API 可用性；别只依赖单一渠道。
- 会话实践：在一个 session 内持续推进任务更高效，但当想到无关问题时用 /btw 以免污染主上下文；需要时用 fork 建分支保持历史清晰。
