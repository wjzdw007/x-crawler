**新工具/技术**
- PocketJS：在索尼 PSP（32MB 内存）上移植 QuickJS，结合标准版 SolidJS 和 Vue Vapor，加编译时 Tailwind，实现极低内存下的流畅 UI（8MB 下 60FPS）。
- Claude Fable 5：Anthropic 的高能力模型变体，支持长时间运行、自我测试，并新增 /goal 与 workflows 用于持续目标驱动与验证。
- Claude Code 平台改进：大幅减少系统提示词（去“捆绑”），转而以上下文驱动模型行为，释放模型本身的想象力与能力悬余。

**核心观点/方法论**
- 把模型当“思维伙伴”：早期让模型参与设计与发问，可在实现前发现可行性和需求盲点，减少返工风险。
- 给上下文而不是过多约束：提供情境信息胜过具体示例，过多示例可能限制模型创造性，反而降低效果。
- 设定目标并验证：用 /goal 与 workflows 让模型持续推进并自动化验证每个子任务，提升可靠性和可审计性。
- 发掘未知并记录偏差：主动做“盲区扫描”、生成多种原型、记录每个偏离决策点，便于事后复盘与把控风险。
- 打破常规、提高野心：在可行性上限被提升时，应尝试更大胆的目标，而不是先行做取舍以免错失可能性。

**实践经验/案例**
- PocketJS 实证了在极限硬件上运行现代 Web UI 的可能性：QuickJS + Solid/Vue + 编译期样式在 8MB 下能完成 60FPS 动画。
- Thariq 的实操发现：Fable 可连续运行数小时并自测，产出的代码常优于人工，需要更多“指引方向”而非持续监督。
- /goal 与 workflows 用法：先写规范，再让模型“设目标→用工作流验证→提交差异报告”，可让模型更自主且结果可核查。
- 具体技巧：让模型先做盲区扫描、提出实施前的面试式问题、生成四种风格原型、并在执行时记录偏离点以便审查。
- 成果举例：用 Fable 在数小时内完成过去需数周的工作（如一场演讲的全部 PPT），说明效率与创意上限被实际推高。
