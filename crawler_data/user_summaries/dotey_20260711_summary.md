**核心观点/方法论**（如有）
- 观点1: UI 是“面子”，代码是“里子”——强调外观比内在更易被大众直观评价。
- 为什么重要: 外观影响首印象与接受度，决定用户是否愿意尝试产品；代码质量虽关键但不易被普通用户感知。
- 观点2: 人们更容易容忍“AI味”的代码，却对“AI味”的UI嗤之以鼻——说明审美与信任对技术采用有不同标准。
- 为什么重要: 视觉上的“模板化/机器人感”会削弱品牌差异化和用户满意度，需要在AI驱动的设计中谨慎处理。

**实践经验/案例**（如有）
- 经验1: 产品决策不能只追求后端效率（AI生成代码），前端视觉与交互也要投入资源维护。
- 经验2: 将AI用于设计时应做“去AI化”或风格化处理，避免显而易见的模板化UI。
- 经验3: 工程团队要维持代码质量作为长期竞争力，产品/设计团队要保障UI的辨识度与审美。
- 经验4: 可通过设计系统、人工复核和微交互等手段，平衡AI带来的规模化与用户体验。
- 经验5: 用“面子/里子”比喻有助于跨团队对齐优先级：先保证面子以赢得用户注意，再逐步打磨里子。
