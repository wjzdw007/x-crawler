**新工具/技术**（如有）
- MOSS-Transcribe-Diarize-0.9B（OpenMOSS）：端到端的多人长音频转写+说话人标注模型，0.9B 参数，支持超长上下文（128K），可一次处理约 90 分钟音频，Apache-2.0 可商用。  
- BaoCut + Skill：dotey 在 BaoCut 中集成了上述模型，把视频/音频转为带说话人和时间戳的结构化转录，配合 Agent 能做翻译/剪辑等下游操作。  
- Qwen3-ASR + Qwen3-ForcedAligner（对比技术）：更快、支持标点和词级对齐，资源占用低（0.6b 已足够），适合追求速度与精度的本地部署场景。

**核心观点/方法论**（如有）
- 端到端一体化模型能显著简化流水线：MOSS 直接输出“说了什么、谁说的、什么时候说”的结构化结果，省去了单独的 ASR→分离→对齐级联工程，降低工程复杂度与集成成本。重要性在于能把长音频转写流程从多模型编排变成单模型调用，便于落地和自动化。  
- 把交付过程沉淀为可复用知识/Skills（FDE 思路）：每个项目都向下一个项目“打工”，将沟通、交付、修改原因结构化成 Agent 知识库，形成复利式的交付体系。重要性在于把个人经验转成组织资产，提高效率并降低对单一人的依赖。

**实践经验/案例**（如有）
- dotey 的集成实测：MOSS-Transcribe-Diarize 能一次性处理长音频并给出精确时间戳和说话人对齐，但转录速度比 qwen3-asr-0.6b 慢、当前不支持标点、自定义 Prompt 与热词在他测试中效果有限。  
- 性能与成本权衡：在 4090 单卡上 RTF 可低至 0.017（示例），5–10 分钟录音约 30 秒完成，适合需要一次性长上下文的场景；若更看重速度、标点和词级时间戳，qwen3-asr + forced aligner 是更实际的选择。  
- 产品化建议：对需要后续人工编辑/翻译/剪辑的流程（如 BaoCut Skill 的视频转录翻译），优先选能直接产出结构化输出的模型；同时把每次处理的元数据和纠错信息回流到技能库，推动 FDE 式的交付飞轮。
