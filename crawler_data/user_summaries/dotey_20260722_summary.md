**新工具/技术**  
- HuggingFace 用的是 GLM 5.2：说明主流平台开始采用更大一代模型作为默认推理后端，利于提升基线能力与兼容性。  
- 拼贴动画 B-roll Skill（MIT 开源）：一套从文稿到拼贴静帧再到 Gemini Omni Flash 组装动画的流水线，依赖 Codex（静帧由内置 image_gen 生成）。  
- “故事转手绘视频” Skill（开源）：把中文故事自动拆分分镜、生成黑白→上色手绘动画并输出静音 MP4，保留原文节奏与安全构图。  
- Codex 的服务端加密上下文压缩 + Pi 插件：OpenAI 在服务端做的压缩能显著提升长任务表现，Pi 可通过扩展启用相同机制。  
- AIHOT（AI 资讯站）：一个实时抓取、清洗、结构化并用多个大模型参与的资讯聚合系统（后端复杂，免费对外）。  

**核心观点/方法论**  
- 人机协作优先：用 AI 生成素材/草稿，人类负责筛选与组织以保持思考能力与产出质量（避免完全外包思维）。  
- 三重确认闸门控制成本与质量：先免费改文字、次级便宜重生成图片，只有通过静帧确认才触发昂贵的视频渲染。  
- 保留原文与安全构图很重要：自动化分镜与画面合成要尊重原文叙事节奏并避免裁切关键内容，提升可用性与用户接受度。  
- 服务端上下文压缩是提升长上下文任务表现的关键工程点：不同 harness 默认行为不同，需显式启用或复现以保证一致性。  
- 开源化与模块化能加速社区改进与生态扩展：Skill 型项目把复杂流程拆成可复用模块，利于迭代与贡献。  
- 社区性产品/平台也需强化内容治理：对抗协调式垃圾回复，建议提供“批量/协同垃圾举报”并用基础 AI 评估可信度。  

**实践经验/案例**  
- B-roll 与故事转手绘两个 Skill 已开源（MIT），流程包含多轮人工确认与 QA，能把文稿快速产出为可编辑视频素材。  
- 故事 Skill 已给出运营数据示例（短期内显著拉升播放与涨粉），说明定位好且流程闭环的工具能快速产生效果。  
- 在 Pi 上装 Codex 压缩扩展能显著提升长运行任务的稳定性，实践证明服务端 compaction 有实际收益。  
- 打造高质量 AI 产品成本高：AIHOT 的经验显示，数据抓取—清洗—聚类—精选每一步都需要大量工程与回测。  
- 实践建议：把 AI 当作“素材引擎”，在输出后手动提炼（例如把 LLM 输出归纳为自己的要点），既省力又保留能力。
