**新工具/技术**
- cloudflare/computer：Cloudflare 的 isolate-run 库，提供轻量“自己的电脑”抽象（workspace + SQLite），在可行时用 isolate 替代容器以节约 CPU 并实现快速横向扩展。  
- pi-mono（推荐学习的 harness 项目）：生产级 harness 源码实例，适合深入研究 CI/运行时集成与工程实践。  
- Claude Code（提及的泄漏源码）：被视为重量级参考（非公开/泄漏），暗示大型闭源系统的实现细节对学习有价值。  
- 《前置部署工程师》开源书：系统化整理 FDE（前置部署工程师）职责与落地方法，免费在 GitHub 可读，可作为岗位/实践手册。  

**核心观点/方法论**
- 推理工程成为独立高价值学科：将训练好的权重做成“快、稳、便宜”的生产级 API 是巨大的商业机会，技术优化能产生数倍性能差异，形成中间商价值。  
- 人才比模型更稀缺：模型泛化后，真正稀缺的是把模型嵌入客户真实业务、产出可衡量回报的工程能力（FDE）。  
- Agent 需要“有状态的电脑”而非简单容器：用 isolate + durable objects 实现轻量隔离能兼顾横向扩展与审计，降低容器压力并优化算力经济学。  
- 不可忽视传统优化思想：索引、查询优化、编译器层次的抽象和成本控制仍然关键——“直接生成结果”会把 token/算力成本问题抬到前台。  
- 中间商繁荣的驱动因素：技术迭代快、信息差大、资本多、叙事吸引 —— 这些条件促使中间层可以通过工程化把能跑的系统做到极致从而获利。  

**实践经验/案例**
- Prefill vs Decode 分离：对长输入先做 prefill，再并行或专用 GPU 做 decode，可大幅提升吞吐与延迟表现。  
- KV Cache + Cache-aware Routing：复用 KV cache、做路由判断能跳过重复计算，缓存命中率直接决定成本与延迟。  
- Speculative Decoding（投机解码）：用小模型预测大模型输出，命中时直接用，常见可带来 2–3× 速度提升。  
- 量化（FP4/FP8 等）+ Day-0 支持：激进量化在很多场景下损失可控；中间商需在模型发布几小时内完成量化、投机头训练和内核适配以抓住热度。  
- 学习路径建议：系统化读、实操一个 harness（推荐把 pi-mono 深入搞透）比泛览多项目更有效。
