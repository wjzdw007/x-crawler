**新工具/技术**（如有）
- Jev / System One（TypeSafe）：一种放弃文本生成、面向嵌入式决策的模型，输出类型安全的结构化结果并带置信度，延迟极低、成本很低，适合作为代码里的“智能 if 语句”。
- Doubao-Seed-2.1-pro（豆包大模型 2.1 Pro）：多模态、Agent 强化的模型版本，增强了证据溯源、多模态写码和视频/图像理解，且图像/视频推理成本显著下降。
- MCP + Deferred Tools：MCP（模型协议）现为无状态并支持 deferred tools（按需加载 schema），减少初始上下文开销、提高工具集可发现性和可扩展性。
- Claude 合并 Cowork 与创作工具：Anthropic 将后台任务模式与聊天合一，并内嵌 Docs/Slides/Design 工具，简化从对话到产物的工作流。

**核心观点/方法论**（如有）
- 团队运转依赖三类人（问题定义者、结果 owner、领域专家），AI 可能把这些角色合并成“超级个体”，带来效率与风险并存：效率提升同时也会集中关键能力点。
- MCP vs CLI：MCP 近来改进很多（无状态、deferred tools、模型 tool-calling 提升），但不是在所有场景都优于 CLI；CLI 在本地、CI、低 token 成本和管道化组合上仍有天然优势。
- 设计取舍优先于表面性能（以 SwiftUI 为例）：把动画放回 app 进程能换来更自然的可交互、可中断体验，但也带来对主线程阻塞的敏感性，这是架构级的权衡。
- 工程化测试原则：以行为为中心、用 BDD、尽量少 mock、分级跑测试并做精准的受影响测试选择，这些做法对 Vibe coding（高频提交）尤为关键。

**实践经验/案例**（如有）
- 豆包在金融投研场景的 Agent 编排：一次核实用了 ~500 个子 Agent、检索 1000+ 网页并交叉海事/卫星数据，说明多 Agent + 多源交叉验证能显著降低幻觉，提升尽调质量。
- 多模态写码与仓库修复：豆包在大规模代码库（示例 ~38.7 万行）上做自主修复测试，报告 ~83% 任务可合并，展示了看图写码和跨文件修 bug 的工程可行性。
- Jev 的演示与定位：在 DOOM 实时操控与 Wikipedia 跳链竞速中展示了每秒多次调用的低延迟优势，明确适合实时决策、批量分类与作为大模型输出的“质检员”。
- CI / 测试优化实践：通过文件级影响追踪、测试分级、合适的 runner 分配与本地 runner 节省成本，可以在高频交付下显著降低测试时间与资源消耗。
