**新工具/技术**
- Jev / System One（TypeSafe AI） — 一类只输出类型安全结构化决策、不生成文本的模型，面向嵌入代码流程的“智能 if”节点，官方宣称显著更快更便宜（低延迟、输出免费）。  
- Doubao-Seed-2.1-pro（豆包 2.1 Pro 0915） — 多模态能力增强，强化 Agent 任务交付、多模态写代码与视频/3D 理解，并降低图像/视频推理的 token 成本。  
- MCP 的 Deferred Tools 特性 — 工具按需加载（defer_loading），初始上下文只放名称和描述，按需检索完整 schema，官方数据在大工具集下能把工具定义上下文压缩约 85%。  
- Claude 的合并入口与创作套件（Claude Docs/Slides/Design） — 将长任务模式与日常聊天统一入口，内置文档/幻灯片/设计协作功能，提升工作流连贯性。

**核心观点/方法论**
- MCP vs CLI：MCP 性能和可控性已经大幅提升但未必在所有场景替代 CLI；关键在于“场景匹配”——终端、token 成本、权限与审计、工具发现等是决策要素。  
- 工具调用能力提升的重要性：模型的 tool-calling 能力变强，既利于 CLI（更准确构造命令和解析输出），也更放大了 MCP 在处理结构化 schema 和多步调用链上的优势。  
- 设计取舍示例（SwiftUI vs Core Animation）：把动画放在 app 进程提高可交互性与中断能力，但会引入对主线程阻塞的敏感性，这是架构层面的权衡。  
- 小团队与超级个体 — AI 趋势可能把定义问题、owner、领域专家三类能力集中到少数“超级个体”上，改变团队分工与生产方式。  
- 类型安全决策器的价值观：在大规模、低延迟或可证伪的自动化判断中，放弃文本生成而以结构化、高置信度输出为目标，能显著降低幻觉与集成成本。

**实践经验/案例**
- 豆包多 Agent 实战：官方示例中为核验企业财报调度了 ~500 个子 Agent、检索 1000+ 网页并跨海事航迹与卫星影像比对，说明多 Agent 编排在尽调/投研场景的可行性与价值。  
- Deferred tools 降本增效：按需加载工具 schema 可在工具众多的平台场景下大幅减小上下文负担，利于 agent 做工具发现与按需调用。  
- Jev 的应用场景实测：用于实时决策（游戏 AI、动态定价）、大规模批量结构化打标、以及作为大模型输出的“质检器”，能在毫秒级响应并返回置信度。  
- MCP 更适合无终端、权限/审计需求和工具发现场景；CLI 更适合已训练过的本地工具、脚本化/CI 场景和 token 效率优先的任务。  
- CI / 测试优化实务：采用文件级或函数级精确测试、测试分级、合理分配 runner 类型与并发度，以及本地 runner 降低托管成本，能显著缓解 Vibe coding 下测试瓶颈。  
- 商业化与配额变化的提醒：订阅服务（如 Claude/Fable）的配额与价值会发生调整，做长期架构/成本评估时需考虑供应方的渐进收紧策略。
