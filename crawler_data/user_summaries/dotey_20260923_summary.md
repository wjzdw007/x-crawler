**新工具/技术**
- Opus 5.5：dotey 在多条推文中提到并比较其表现（尤其是 Max 模式），被描述为“耐用”，用于复杂写作/执行任务，实测比 4.6 Max 约节省 19%。  
- GPT‑6 Astra：作为对比对象出现在大幅 3D 场景提示讨论中，代表高能力模型用于生成复杂交付物。  
- Claude 手机 App（多账号支持）：产品层面利好多账号使用场景，方便在多身份/项目间切换。  
- AGENTS.md / CLAUDE.md（项目说明书约定）：用于让不同 agent 按约定读取项目说明，方便多工具、多 agent 协作与传递上下文。

**核心观点/方法论**
- 复杂任务必须要写方案：一句话不足以传达目标，细节决定实现与架构，方案能建立共识、同步背景并锁定路径，减少返工。  
- 文档驱动的多 agent 流程：用文档确认方向、作为验收标准，Fable/Opus 等角色可分别生成、执行、验收，形成闭环。  
- 先确认方案再同步文档（维护流程）：变更先通过讨论确认解决方案，确认后再把变更同步到文档，避免文档跟进滞后或错误。  
- 不要盲目交付代码：交付前要在浏览器或目标环境实际运行并截图验收，检查渲染、交互、性能与错误。

**实践经验/案例**
- 性能/成本对比：社区实测 5.5 Max 在复杂写作上优于 4.6 Max，且能节省约 19%（成本/资源消耗指标）。  
- 工程交付要求示例：dotey 转发的高质量 3D 场景提示强调“真实 3D 几何、不依赖外部素材、移动/桌面双模式、四个设计镜头、降级模式与验收清单”，展示对可交付产品的严格工程化要求。  
- 多 agent 工作流示例：先写技术方案（人工确认），Fable 写/审查文档，Opus 执行，最后由文档或另一个 agent 做验收，文档同时作为后续维护和归档依据。  
- 产品/特性观察：plan mode 可能被取消，改用快捷键调整 effort level，说明工具设计在向更轻量的交互与效率优化演进。
