**核心观点/方法论**（如有）
- “effort” 是对模型在单任务上投入验证与边界检查深度的刻度（从 low→max）——决定模型会替你做多少假设与自检，影响产出质量与耗时。  
- 以人机协作为中心的迭代流程：先让模型访谈/整理需求，用 low 做快速原型并掌控细节，最后切 high 做验证和边界测试。  
- 成本与缓存意识同等重要：Opus 5.5 在 token/缓存上更便宜，但上下文复用依赖严格的对话头一致性，切模型或中断会大幅提升费用。  
- 确定性与 QA 驱动的生产流程对高质量视频/动画至关重要（种子、静帧检查、分项评分与循环修正）。  

**实践经验/案例**（如有）
- Thariq 的实测（Claude Code）显示：low 适合头脑风暴和快稿，medium 适合日常开发，high/max 用于边界多或需高度独立的复杂任务（如漏洞挖掘、完整 App）。  
- Terminal-Bench 案例（html-js-filter、存储引擎崩溃）说明：边界条件多的题目在高档位成功率显著更高，低档位常因未复现/未测试边界而失败。  
- gsea-proteomics 案例表明：在无人监督的情形下，高档位更能自我试错并得到正确结论；有人在场时可用低档位并通过提问引导模型。  
- Opus 5.5 成本数据与技巧：输入/输出 token 约降 20%，缓存读降 60%，平均会话成本降 ~31%；技巧包括 /clear、/compact 与避免在缓存有效期内切模型。  
- Claude Code 限额策略：5 小时滚动窗口 + 每周上限；Pro/Max/Team 在“收尾额度”与超额使用策略上权限不同，影响长任务自动化的可用性。
