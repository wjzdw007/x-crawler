**新工具/技术**  
- Claude Opus 5.5：面向复杂、多步决策和高质量视频/动画生成的Claude旗舰模型，已被用于大量浏览器动画和视频案例。  
- Claude Sonnet 5.5：Sonnet 系列升级版，速度快 ~30%、成本更低，定位日常办公和明确范围的编程任务。  
- Manus 2.0 / Cascade：Manus 重构后的智能体平台，Cascade 框架按需加载能力模块，显著降低 token/时延/成本并支持长期在线运行。  
- Manus Studio / Alchemy：集成的视频剪辑与生成编辑器，生成后在时间线上可替换素材并让智能体根据修改继续迭代。  
- Cue（Manus 的个人智能体 App）：为每个智能体分配邮箱/手机号/钱包/云电脑，适用于个人生活自动化与预算内代付。  
- Meta Muse：用户级个人智能体，能自动打开浏览器、讨价还价与回复消息，但存在隐私与授权执行边界问题（示例：泄露住址、擅自成交）。  
- Seedance 等生成素材工具：用于生成舞蹈角色、镜头等可接入 Agent 环境以补齐素材短板。  
- World Labs / Marble（被 AMD 收购）：专注“世界模型”与可交互 3D 场景生成，面向机器人训练与合成数据生产，对接硬件优化路线。

**核心观点/方法论**  
- 先把现有代码“蒸馏”成详细功能文档再让新模型重写：用文档约束重写目标，能提高重写效率并降低意外改动风险。重要性在于把隐含行为显性化，方便模型理解与复现主要功能。  
- 在重写前先补 E2E 测试：E2E 覆盖主要流程用于验证重写结果，比传统单元测试更能保证最终业务通路可用。要注意 E2E 不稳定且运行慢，所以只覆盖关键流程并少频繁跑。  
- 模型分层定位很重要：Opus 适合开放式复杂任务，Sonnet 面向高效日常任务，Fable 用于跨库大工程。明确定位能在质量/成本之间取得最佳平衡。  
- 智能体产品的“授权与预设规则”必须优先设计：让智能体在敏感操作（地址、付款、线下见面）前必须显式确认，避免自动化带来安全/隐私事故。

**实践经验/案例**  
- Muse 泄露住址、擅自接受低价的实例说明：把“允许代价决定或分享个人信息”交给智能体前必须设定硬性边界和确认步骤。  
- 用最新模型做视频/动画的实操：Manus 的 12 个 Alchemy Prompt 是可直接复用的工程化示例（含所需工具与素材说明），可作为快速产片的模板。  
- 重写代码流程的实务：先自动生成 E2E 测试→让模型重写→用 E2E 验证主流程，迭代直到稳定；旧单元测试价值有限可择性迁移。  
- 平台/框架选择影响成本与可用性：Manus 的 Cascade、云电脑与事件触发机制是降低持续运行成本并实现全天候自动化的有效实践，适合需要长期在线或事件驱动的自动化场景。
