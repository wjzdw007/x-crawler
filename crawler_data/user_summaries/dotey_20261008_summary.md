**新工具/技术**（如有）
- CC Switch — 一个开源的 AI 开发/切换工具，最近做了大规模重构：侧边栏布局、应用切换和将直连/路由/聚合改为标签切换，提升多模型/多工作流的可用性。
- magpie — 可视化每个 agent 会话的 context window（系统提示、工具、记忆、文件、对话等）并打分，方便定位上下文占用和缓存命中。
- Fable + Opus（代理编排模式）— 把 Fable 作为高级顾问/Tech‑Lead、Opus 做执行子代理，形成方案→执行→验收的闭环，降低人工干预。
- Haiku 5.5（模型/定价提醒）— 模型看似低价，但上下文 >100K 时价格直接翻 5 倍，提醒注意上下文相关的阶梯定价陷阱。

**核心观点/方法论**（如有）
- AI 推理成本在快速下降 — 真实 API 成本远低于极端估算，模型选择、缓存和架构能把月度成本从百万量级压缩到可控范围，长期影响工程经济学。
- 选编程语言是选约束和维护成本 — AI 能写代码但不会替代对可审计源码与边界/权限的需求，语言与工具链的错误预防和生态仍然重要。
- 压低感知价格的策略常见 — 厂商可能为基准/榜单优化定价（如对小上下文友好），实际长期使用应计算大上下文成本。
- 平台政策与合规成为工程约束 — 厂商为模型“福利”和风险管理调整使用政策，影响产品设计（如需人工审核的高风险场景）。

**实践经验/案例**（如有）
- 代理闭环实操（dotey）— 用 /advisor fable 指定 Fable 为顾问，Opus 做执行，要求执行后自动送回顾问验收，可持续派活并形成自我修复流程，节省人工同步成本。
- 会话与上下文管理 — 将最大上下文设为 300K、删除对 1M 限制（CLAUDE_CODE_DISABLE_1M_CONTEXT），配合 /autocompact 管理长期会话以平衡能力与成本。
- 可观测性落地（magpie）— 对多 agent 系统可视化 context 构成和缓存命中，能快速定位哪类输入占用资源并优化缓存策略。
- UI/UX 改进带来效率（CC Switch）— 侧边栏与标签化工作方式把全局功能集中，降低多模型/多工作流切换成本，适合团队化使用场景。
- 合规与产品流程调整（Anthropic 政策）— 对医疗、金融、武器等高风险输出需加入人工审核并在界面告知 AI 生成来源；同时注意平台对“虐待模型”等行为的限制不会影响正常研究/创作。
