**dotey 的 AI 观察（2026年11月11日）**

**新工具/技术**
- Claude Whiteboards、Claude Sheets、Claude Data：白板与表格进入 Artifacts，支持人机实时协作；Claude Data 强化认证指标、实时分享和数据故事。
- 斯坦福 CS329Z“Engineering AI Agents”：课程资料公开，作业一要求不用 Agent 框架、从零写 agent harness，作业二要求设计 Terminal-Bench 风格评测题。
- Gemini Decisions API：不生成文本，只做是非题、单选题和打分题，单次最多 1000 个问题，输出不计费，适合路由、工具选择和安全判断。
- Fable 5.2 案例：可在浏览器生成 3D 卡丁车游戏，也能用 Python 驱动 Blender 做短片，展示“代码生成内容”的快速原型能力。

**核心观点/方法论**
- 软件形态正从“给人用”转向“给 Agent 用、人审查微调”：Google Docs 把 Office 云端化，Claude Artifacts 则把软件使用主体从人变成 Agent。
- Agent 时代软件设计重心转向“可验收”：多人协作变成人机协作，直接操作变成标记与评论，人主导变成 Agent 先采访再实施。
- 用 AI 不应先问“你会什么”，而应直接给目标和验收标准：模型并不清楚自身能力边界和可用工具，领导式给方向、上下文与工具支持更有效。
- 能力与可靠性存在差距：评测分数最高的 Agent 不一定最可靠，记忆压缩、安全约束和失败可恢复性都会影响实际表现。
- 世界模型与通用 Agent 不是同一问题：前者关注空间表征与环境预测，后者关注下一步行动，二者未来会融合而非简单互相取代。

**实践经验/案例**
- 可复用工作流：给 AI 目标、验收标准、必要上下文和工具，做完后看差距；再判断是上下文不足、工具缺失、标准不清还是模型能力不足。
- 每次模型升级后应重试旧任务：以前做不到或需繁琐交代的事，可能在新模型上直接简化，值得建立“升级后复测”习惯。
- CS329Z 作业强调测试驱动和低成本验证：几美元 API 额度即可从零写 Agent harness，先让测试失败再逐项通过，比只看教程更有效。
- Fable 5.2 的程序化美术适合快速原型和网页体验，但不等于真正 3A：传统游戏大量体积在美术、音乐资产，生成式方案胜在速度和可玩性，精美度与算力成本仍需权衡。
- Anthropic 新条款是合规红线：物理位置、企业注册地、股权控制三重限制，对依赖 Claude 的跨境团队和投资结构需提前评估。
