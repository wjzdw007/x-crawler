**dotey 2026年11月16日推文分析**

**新工具/技术**
- **主会话 + Thread 双层 Agent 模式**：主会话负责甄别、路由和调度，Thread 承接具体任务；主会话用 Sonnet 5.5 级别即可，Thread 则用更强的 Opus 5.5。
- **Prompt Caching + Session 检索工具组合**：主会话缓存过期后只发送最新几条消息，再靠检索工具补齐上下文；Thread 则在缓存临近过期（约 50 分钟/1 小时）时主动压缩上下文。

**核心观点/方法论**
- **调度层不必用最强模型**：主会话像公司前台，不需要懂专业细节，只需知道“什么任务该找谁”；执行层才值得投入强模型，更科学的做法是按任务难度动态选模型。
- **区分 Bot 主会话与具体研究任务**：Bot 是“单主会话收消息→转发到 Thread”，研究任务则是“强模型计划、调度、验收 + 强模型执行”，两种场景不矛盾，关键是别让主会话直接干重活。
- **缓存策略要按会话形态定制**：主会话消息稀疏、缓存命中难，Thread 集中对话、缓存利用率高；用同一套缓存策略会浪费 Token。
- **Personal Agent 的瓶颈在生态围墙**（转推）：上一代移动互联网做得太成功，平台封闭导致 Personal Agent 难以打通；这决定了 Agent 产品短期更可能停留在“单点任务”而非“跨应用代办”。
- **黄仁勋事件的两面观察**：转推批评媒体从传闻到传闻的叙事链条；原创整理 Altman 回应，强调黄仁勋的独特价值、行业需求韧性，但对“该不该回来”保持谨慎。

**实践经验/案例**
- **Claude Project 实测配置**：主会话 Sonnet 5.5、子任务 Opus 5.5，优化后 Token 消耗可接受，说明分层模型搭配在成本与效果间可落地。
- **数学研究 Bot 案例**：主会话识别到复杂数学需求后，不自己研究，而是新建 Thread 原样转发需求，由 Fable 做计划调度验收、Opus 执行具体子任务。
- **缓存压缩阈值**：Thread 在缓存约 50 分钟（按 1 小时缓存计）时压缩上下文，避免过期后重发全部历史，是可复用的工程细节。
