**核心观点/方法论**
- **“部分理解”是常态，而非缺陷**：大型项目里程序员本就只懂自己负责的那部分，Agent 在单次上下文中也不可能理解整个项目；理解不完整不阻碍维护与修改，关键是验证兜底。
- **验证体系分三层**：自动化测试是第一道防线，但不能过度依赖（测试本身可能有错）；Code Review 是知识传承手段，如今只能让 AI 审大部分、人审最关键部分；第三层是让 Agent 自证产出。
- **循环工程优于完全自动化**：dotey 转发 @guyingjie129 的观点——人应作为系统的一部分，承担驱动、引导、验收与反馈；人真正想要的不是全自动，而是把不擅长、不喜欢的工作交给机器。
- **反馈要直达维护者**：吐槽要 @ 具体负责人（如 @shengzheyao）才有机会进入修复清单，而非停留在情绪表达。

**实践经验/案例**
- **Agent 截图验收法**：开发新功能要求提供功能截图，修 bug 要求提供修改前后对比截图；进阶用法是让 Agent 自行模拟 API 响应、动态生成多场景截图，完全不需要服务端配合。
- **具体可复现的痛点反馈**：跨 workspace 打开文件时每个文件都要单独授权，而非一次性授权，这是 dotey 当前最烦的问题，也正是官方承诺修复的清单项。
- **黎曼猜想的双线对照**：机器验证说“没错”但人还没读懂；同一天斯坦福发布的纯人工证明草稿，几小时后就被 AI 报告问题——可机器验证性正在成为新的证明标准。
