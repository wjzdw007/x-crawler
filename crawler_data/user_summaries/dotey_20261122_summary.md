dotey（宝玉，AI Engineer，27 万粉丝）当日主线是“Agent 到底能不能信”，并穿插工具发布与安全提醒。

**新工具/技术**

- **Claude Design（含本地版）**：与 Open Artifact 搭配做产品原型，几分钟就能输出接近终稿的界面，被转推用户称为“产品人员的福音”。

**核心观点/方法论**
- 长文《Agent 说“验证完了”，怎么才能真的信它？》给出五条：① 不要依赖对抗式验证，多个 Agent 互查时若缺统一验收标准，会越改越偏、白烧 Token；② 先定义“什么叫做好了”，并给出一个 Agent 能自验的环境（如“网页截图与设计稿像素级一致”）；③ 越早验证返工越少，可行性分析→原型→系统设计这三关不能因 Vibe Coding 而省略；④ 让 Agent 交证据（截图、录屏、可视化 HTML 报告），把人的验收成本压到最低；⑤ 代码审查聚焦 P0/P1 与安全性能，PR 要小，细节放过。
- 回应 @yangyi 的补充：不是否定 Agent 自检的价值，而是不要过度依赖，标准必须清晰统一；关键节点坚持“自检 + 他检”交叉验证，多花 Token 换稳定性。
- 转推 @guyingjie129：Vibe Coding 让开发者先失去对代码细节的掌控，再在程序抽象性质层面获得更强的宏观掌控，是“先退化再进化”。
- 引用 Yann LeCun 转述的皮亚杰名言：“智力不是你知道什么，而是当你不知道时你做了什么”——正好对应 Agent 在未知情境下的验证与纠错能力。

**实践经验/案例**
- 可复用的证据清单：新功能给截图、修 bug 给前后对比图、让 Agent 自造 API 模拟数据批量生成多场景截图，完全不需要服务端配合。
- 人的注意力才是瓶颈：Antigravity 跨 Workspace 每读一个文件都要手工确认，体验接近崩溃，所以要把人工确认点设计得又少又关键。
- 安全提醒：当天发现冒充账号与钓鱼链接，公开发文警示粉丝不要点击，体现其对账号安全与信息真实性的关注。
